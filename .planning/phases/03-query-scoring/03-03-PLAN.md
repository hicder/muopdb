  <files>rs/index/src/collection/text_search.rs</files>
  <action>Create `rs/index/src/collection/text_search.rs` with cross-segment aggregation:

1. **SegmentBm25Context** struct - per-segment search context:
   - `segment_name: String` - identifier for the segment
   - `stats_dir: String` - path to bm25_stats/ for this segment
   - `terms_dir: String` - path to terms/ for this segment
   - `searcher: Bm25Searcher` - initialized searcher for this segment
   
   Constructor takes segment directory and initializes Bm25Searcher.

2. **CrossSegmentTextSearcher** struct - manages multi-segment search:
   - `segments: Vec<SegmentBm25Context>` - all segments with BM25 data
   - `global_k: usize` - global top-K to return
   
   Constructor: `new(segment_dirs: Vec<(String, String, String)>, config: BM25Config, global_k: usize) -> Result<Self>`
   - For each segment tuple (name, stats_dir, terms_dir), create SegmentBm25Context

3. **search_cross_segment()** method - implements QRY-04:
   ```rust
   pub fn search(&self, query_text: &str, user_id: u128) -> Result<CrossSegmentResults>
   ```
   - Create Bm25Query for each segment with text, user_id, max_results
   - For each segment:
     - Call segment.searcher.top_k_search(&query)
     - Collect local results
   - Aggregate all segment results:
     - Use HashMap<u128, (f32, u32)> to deduplicate by doc_id (map from external doc_id)
     - Convert point_id to doc_id using segment's get_doc_id method
     - If same doc appears in multiple segments, keep highest score
   - Select global top-K from aggregated results using TopKSelector
   - Return CrossSegmentResults

4. **CrossSegmentResult** struct - final search result:
   - `doc_id: u128` - external document ID
   - `score: f32` - aggregated BM25 score
   - `segment_hits: Vec<SegmentHit>` - which segments contributed (for debugging)

5. **CrossSegmentResults** struct - container:
   - `results: Vec<CrossSegmentResult>` - sorted by score descending
   - `total_segments_searched: usize` - how many segments were queried
   - `total_docs_considered: usize` - total before deduplication

Use anyhow::Result for error handling. The key insight: doc_ids are external u128 identifiers that are unique across segments, while point_ids are internal u32 per-segment identifiers.</action>

   - Deduplicate candidates by doc_id (keep highest score if duplicates):

   - Select global top K using TopKSelector
   - Return sorted Vec<(u128, f32)>
